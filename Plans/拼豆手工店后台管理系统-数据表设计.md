# 拼豆手工店后台管理系统数据表设计

## 1. 设计说明

本文档用于说明手工品类、客户、客户账户、充值记录、消费记录、桌位和开台会话七张表的数据结构及表间关系，仅作为数据库设计依据，不包含 SQL 或程序代码。

### 1.1 通用约定

| 项目 | 约定 |
| --- | --- |
| 参考数据库 | SQLite 3 |
| 命名方式 | 表名、字段名统一使用小写蛇形命名 |
| 业务字段映射 | TypeScript 字段使用小驼峰命名，并通过映射转换，例如 `customer_phone` 对应 `customerPhone` |
| 字段类型 | 使用 SQLite 原生存储类型：ID、时长和金额使用 `INTEGER`，文本和时间使用 `TEXT` |
| 主键 | 业务实体及流水记录使用 `INTEGER` 主键，由 SQLite 自动分配；客户账户直接使用客户 ID 作为主键 |
| 金额 | 统一以人民币分为单位，采用 `INTEGER` 存储；业务层负责元与分的转换，不使用浮点数 |
| 时间 | 采用 `TEXT` 保存 UTC 时间，格式为 `YYYY-MM-DD HH:MM:SS`，默认使用 `CURRENT_TIMESTAMP`；数据库通过 `GLOB` 检查约束校验格式，写入时不得使用带 `T`、`Z` 的 ISO 8601 文本 |
| 文本长度 | 表中的长度为设计上限；SQLite 的 `TEXT` 不自动限制长度，需通过检查约束或业务校验保证；非空文本字段同时要求去空格后不为空串 |
| 消费时长 | 统一以分钟为单位，使用 `INTEGER` 存储 |
| 空值 | “是否为空”为“否”的字段必须在写入时提供有效值，或具有明确的默认值 |
| 逻辑规则 | 金额范围、充值平台等检查约束由数据库约束与业务校验共同保证 |
| 外键启用 | SQLite 外键约束需在每个数据库连接中显式启用，否则外键不会自动生效 |

## 2. 数据表结构

### 2.1 手工品类表（`craft_category`）

用于维护拼豆及其他手工项目的分类信息。

| 字段含义 | 字段名 | 数据类型 | 长度/精度 | 是否为空 | 键与约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 手工品类 ID | `category_id` | `INTEGER` | — | 否 | 主键，自动分配 | 无 | 品类唯一标识 |
| 品类名 | `category_name` | `TEXT` | 50 | 否 | 唯一约束 | 无 | 同一品类名不可重复 |
| 品类状态 | `status` | `INTEGER` | — | 否 | 检查 `status IN (1, 2)` | 1 | 状态数字枚举：1=上架、2=下架；展示文案由前端映射表/i18n 负责，便于后续状态扩展与多语言 |
| 备注 | `remark` | `TEXT` | 500 | 是 | — | 无 | 品类补充说明，可空 |
| 创建时间 | `create_time` | `TEXT` | — | 否 | — | `CURRENT_TIMESTAMP` | 品类创建时间 |
| 修改时间 | `update_time` | `TEXT` | — | 否 | — | `CURRENT_TIMESTAMP` | 品类信息最后修改时间，由业务逻辑在更新（含状态切换）时刷新 |

**索引与约束**

- 主键索引：`category_id`。
- 唯一索引 `uk_craft_category_name`：`category_name`，避免重复品类。

### 2.2 客户表（`customer`）

用于保存客户的基本资料及微信信息。原始需求中重复出现的“备注”合并为一个 `remark` 字段。

| 字段含义 | 字段名 | 数据类型 | 长度/精度 | 是否为空 | 键与约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 客户 ID | `customer_id` | `INTEGER` | — | 否 | 主键，自动分配 | 无 | 客户唯一标识 |
| 客户名 | `customer_name` | `TEXT` | 50 | 否 | — | 无 | 客户姓名或店内称呼 |
| 客户手机 | `customer_phone` | `TEXT` | 20 | 否 | 唯一约束 | 无 | 使用字符类型以保留前导零及国际区号 |
| 微信 ID | `wechat_id` | `TEXT` | 64 | 是 | 非空值唯一 | 无 | 客户微信号或业务侧微信标识 |
| 微信名 | `wechat_name` | `TEXT` | 100 | 是 | — | 无 | 微信昵称，可重复 |
| 备注 | `remark` | `TEXT` | 500 | 是 | — | 无 | 客户偏好、注意事项等补充信息 |
| 创建时间 | `create_time` | `TEXT` | — | 否 | — | `CURRENT_TIMESTAMP` | 客户资料创建时间 |
| 修改时间 | `update_time` | `TEXT` | — | 否 | — | `CURRENT_TIMESTAMP` | 客户资料最后修改时间，由业务逻辑或触发器在更新时刷新 |

**索引与约束**

- 主键索引：`customer_id`。
- 唯一索引 `uk_customer_phone`：`customer_phone`，避免手机号重复建档。
- 唯一索引 `uk_customer_wechat_id`：`wechat_id`；未填写微信 ID 的记录允许为 `NULL`。
- 普通索引 `idx_customer_name`：`customer_name`，支持按客户名查询。

### 2.3 客户账户表（`customer_account`）

用于保存客户当前预存余额，每位客户最多对应一条账户记录。

| 字段含义 | 字段名 | 数据类型 | 长度/精度 | 是否为空 | 键与约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 客户 ID | `customer_id` | `INTEGER` | — | 否 | 主键，外键 | 无 | 引用 `customer.customer_id`，同时保证一对一关系 |
| 余额 | `balance_cents` | `INTEGER` | — | 否 | 检查 `balance_cents >= 0` | 0 | 当前可用余额，单位为人民币分 |

**索引与约束**

- 主键索引：`customer_id`，同时充当客户账户与客户的一对一约束。
- 外键 `fk_account_customer`：`customer_id` 引用客户表；客户存在账户时不允许直接删除客户。

### 2.4 充值记录表（`recharge_record`）

用于记录客户的每笔充值。补充独立的充值记录 ID，确保每笔流水均可唯一识别。

| 字段含义 | 字段名 | 数据类型 | 长度/精度 | 是否为空 | 键与约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 充值记录 ID | `recharge_id` | `INTEGER` | — | 否 | 主键，自动分配 | 无 | 每笔充值的唯一标识 |
| 客户 ID | `customer_id` | `INTEGER` | — | 否 | 外键 | 无 | 引用 `customer.customer_id` |
| 金额 | `amount_cents` | `INTEGER` | — | 否 | 检查 `amount_cents > 0` | 无 | 本次充值金额，单位为人民币分 |
| 平台 | `platform` | `TEXT` | 20 | 否 | 仅允许“微信”“支付宝”“现金” | 无 | 实际充值渠道 |
| 充值时间 | `recharge_time` | `TEXT` | — | 否 | — | `CURRENT_TIMESTAMP` | 充值完成时间 |

**索引与约束**

- 主键索引：`recharge_id`。
- 外键 `fk_recharge_customer`：`customer_id` 引用客户表。
- 组合索引 `idx_recharge_customer_time`：`customer_id`、`recharge_time`，支持查询指定客户的充值历史。
- 平台取值约束：`platform` 只能是“微信”“支付宝”或“现金”，不使用数据库枚举类型，便于后续扩展。

### 2.5 消费记录表（`consumption_record`）

用于记录客户每次手工消费的品类、时长和金额。补充独立的消费记录 ID，确保每笔流水均可唯一识别。

| 字段含义 | 字段名 | 数据类型 | 长度/精度 | 是否为空 | 键与约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 消费记录 ID | `consumption_id` | `INTEGER` | — | 否 | 主键，自动分配 | 无 | 每笔消费的唯一标识 |
| 客户 ID | `customer_id` | `INTEGER` | — | 否 | 外键 | 无 | 引用 `customer.customer_id` |
| 手工品类 ID | `category_id` | `INTEGER` | — | 否 | 外键 | 无 | 引用 `craft_category.category_id` |
| 时长 | `duration_minutes` | `INTEGER` | — | 否 | 检查 `duration_minutes >= 0` | 无 | 本次消费时长，单位为分钟 |
| 消费金额 | `consumption_amount_cents` | `INTEGER` | — | 否 | 检查 `consumption_amount_cents >= 0` | 无 | 本次实际消费金额，单位为人民币分 |
| 桌号 | `table_number` | `INTEGER` | — | 是 | 检查 `table_number IS NULL OR table_number >= 1` | 无 | 本次消费所在桌号，`NULL` 表示未指定 |
| 是否全天 | `is_full_day` | `INTEGER` | — | 是 | 检查 `is_full_day IS NULL OR is_full_day IN (0, 1)` | 无 | 本次消费时长是否全天：1=全天、0=否，`NULL` 表示未指定 |
| 开台会话 ID | `session_id` | `INTEGER` | — | 是 | 外键，可为空 | `NULL` | 引用 `table_session.session_id`；由开台/续时产生的流水才有值，手工录入的历史流水为空 |

**索引与约束**

- 主键索引：`consumption_id`。
- 外键 `fk_consumption_customer`：`customer_id` 引用客户表。
- 外键 `fk_consumption_category`：`category_id` 引用手工品类表。
- 外键 `fk_consumption_session`：`session_id` 引用开台会话表，删除会话时置空。
- 普通索引 `idx_consumption_customer`：`customer_id`，支持查询客户消费记录。
- 普通索引 `idx_consumption_category`：`category_id`，支持按品类统计消费情况。
- 普通索引 `idx_consumption_session`：`session_id`，支持按开台会话追溯消费流水。

### 2.6 桌位表（`store_table`）

用于维护门店的全部座位。全场固定 18 个座位，每个座位即一个可独立开台、独立计时的桌位；分区（吧台、A/B/C 桌）、展示名与看板坐标属于前端表现层，不落库。

| 字段含义 | 字段名 | 数据类型 | 长度/精度 | 是否为空 | 键与约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 桌位 ID | `table_id` | `INTEGER` | — | 否 | 主键，自动分配 | 无 | 座位唯一标识 |
| 座位号 | `seat_no` | `INTEGER` | — | 否 | 唯一约束；检查 `seat_no BETWEEN 1 AND 18` | 无 | 1~6 为吧台位，7~10 / 11~14 / 15~18 分别为三组四人桌 |
| 创建时间 | `create_time` | `TEXT` | — | 否 | 检查时间格式 | `CURRENT_TIMESTAMP` | 座位初始化时间 |
| 修改时间 | `update_time` | `TEXT` | — | 否 | 检查时间格式 | `CURRENT_TIMESTAMP` | 座位信息最后修改时间 |

**索引与约束**

- 主键索引：`table_id`。
- 唯一索引 `uk_store_table_seat_no`：`seat_no`，避免重复座位号。
- 座位号为静态基础数据，不随看板布局调整而变化。

### 2.7 开台会话表（`table_session`）

用于记录某座位的一次开台消费：购买时长、计划结束时间、累计金额与时长，以及当前状态。倒计时由前端依据 `planned_end_time` 与服务端时间计算。

| 字段含义 | 字段名 | 数据类型 | 长度/精度 | 是否为空 | 键与约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 会话 ID | `session_id` | `INTEGER` | — | 否 | 主键，自动分配 | 无 | 一次开台的唯一标识 |
| 桌位 ID | `table_id` | `INTEGER` | — | 否 | 外键 | 无 | 引用 `store_table.table_id` |
| 客户 ID | `customer_id` | `INTEGER` | — | 否 | 外键 | 无 | 引用 `customer.customer_id` |
| 手工品类 ID | `category_id` | `INTEGER` | — | 否 | 外键 | 无 | 引用 `craft_category.category_id` |
| 会话状态 | `status` | `INTEGER` | — | 否 | 检查 `status IN (1, 2)` | 1 | 1=使用中、2=已结束 |
| 购买时长 | `planned_duration_minutes` | `INTEGER` | — | 否 | 检查 `> 0` | 无 | 开台与续时累计的购买分钟数 |
| 开台时间 | `start_time` | `TEXT` | — | 否 | 检查时间格式 | 无 | 首次开台的 UTC 时间 |
| 计划结束时间 | `planned_end_time` | `TEXT` | — | 否 | 检查时间格式 | 无 | 开台时间 + 购买时长；续时后从较晚者继续累加 |
| 累计金额 | `total_amount_cents` | `INTEGER` | — | 否 | 检查 `>= 0` | 0 | 开台与续时累计消费金额，单位分 |
| 累计时长 | `total_duration_minutes` | `INTEGER` | — | 否 | 检查 `>= 0` | 0 | 开台与续时累计分钟数 |
| 结束时间 | `close_time` | `TEXT` | — | 是 | 检查时间格式 | `NULL` | 手动结束会话的时间 |
| 创建时间 | `create_time` | `TEXT` | — | 否 | 检查时间格式 | `CURRENT_TIMESTAMP` | 会话创建时间 |
| 修改时间 | `update_time` | `TEXT` | — | 否 | 检查时间格式 | `CURRENT_TIMESTAMP` | 会话最后修改时间 |

**索引与约束**

- 主键索引：`session_id`。
- 外键 `table_id`：引用桌位表；`customer_id`、`category_id` 分别引用客户表与手工品类表。
- 部分唯一索引 `uk_table_session_active`：`table_id WHERE status = 1`，保证同一座位同时只有一个进行中的会话。
- 普通索引 `idx_table_session_customer`：`customer_id`，支持查询客户开台历史。
- 普通索引 `idx_table_session_start`：`start_time`，支持按日汇总当日开台次数与时长。

### 2.8 检查约束汇总

所有表均为严格表，除主键、唯一、外键约束外，另由数据库检查约束保证以下规则：

| 表 | 检查约束 |
| --- | --- |
| `schema_migrations` | `version`、`name` 去空格后非空；`executed_at` 符合 `YYYY-MM-DD HH:MM:SS` |
| `craft_category` | `category_name` 去空格后非空且长度不超过 50；`status` 只能是 1 或 2（1=上架、2=下架）；`remark` 长度为 `NULL` 或不超过 500；`create_time`、`update_time` 符合 `YYYY-MM-DD HH:MM:SS` |
| `customer` | `customer_name` 去空格后非空且长度不超过 50；`customer_phone` 去空格后非空且长度不超过 20；`wechat_id` 为 `NULL` 或去空格后非空且长度不超过 64；`wechat_name` 长度为 `NULL` 或不超过 100；`remark` 长度为 `NULL` 或不超过 500；`create_time`、`update_time` 符合 `YYYY-MM-DD HH:MM:SS` |
| `customer_account` | `balance_cents >= 0` |
| `recharge_record` | `amount_cents > 0`；`platform` 去空格后非空、长度不超过 20，且只能是“微信”“支付宝”“现金”；`recharge_time` 符合 `YYYY-MM-DD HH:MM:SS` |
| `consumption_record` | `duration_minutes >= 0`；`consumption_amount_cents >= 0`；`table_number` 为 `NULL` 或 `>= 1`；`is_full_day` 为 `NULL` 或只能是 0/1 |
| `consumption_record` | `duration_minutes >= 0`；`consumption_amount_cents >= 0`；`session_id` 为 `NULL` 或引用已存在的会话 |
| `store_table` | `seat_no BETWEEN 1 AND 18`；`create_time`、`update_time` 符合 `YYYY-MM-DD HH:MM:SS` |
| `table_session` | `status` 只能是 1 或 2；`planned_duration_minutes > 0`；`total_duration_minutes >= 0`；`total_amount_cents >= 0`；`start_time`、`planned_end_time`、`close_time`、`create_time`、`update_time` 符合 `YYYY-MM-DD HH:MM:SS` |

说明：时间格式检查使用 `GLOB` 模式匹配，业务代码写入时间时必须使用 `YYYY-MM-DD HH:MM:SS` 形式的 UTC 文本，例如 `datetime('now')` 或等价格式化结果，不得写入带 `T`、`Z` 或不含时分秒的文本。

## 3. 表间关系

| 主表 | 从表 | 关系 | 关联字段 | 关系说明 |
| --- | --- | --- | --- | --- |
| `customer` | `customer_account` | 一对一 | `customer_account.customer_id → customer.customer_id` | 每位客户对应一条账户记录；从表的客户 ID 同时是主键和外键 |
| `customer` | `recharge_record` | 一对多 | `recharge_record.customer_id → customer.customer_id` | 一位客户可有多笔充值，每笔充值仅属于一位客户 |
| `customer` | `consumption_record` | 一对多 | `consumption_record.customer_id → customer.customer_id` | 一位客户可有多笔消费，每笔消费仅属于一位客户 |
| `craft_category` | `consumption_record` | 一对多 | `consumption_record.category_id → craft_category.category_id` | 一个手工品类可出现在多笔消费中，每笔消费仅关联一个品类 |
| `store_table` | `table_session` | 一对多 | `table_session.table_id → store_table.table_id` | 一个座位可产生多次开台；同一时刻最多一条 `status = 1` 的会话 |
| `customer` | `table_session` | 一对多 | `table_session.customer_id → customer.customer_id` | 一位客户可多次开台 |
| `craft_category` | `table_session` | 一对多 | `table_session.category_id → craft_category.category_id` | 一次开台对应一个手工品类 |
| `table_session` | `consumption_record` | 一对多 | `consumption_record.session_id → table_session.session_id` | 开台与续时各写入一笔消费流水，便于按会话追溯 |

客户与手工品类之间不设置直接外键，两者通过消费记录形成间接关联。除 `consumption_record.session_id` 为可空关联外，其余外键字段均不能为空，子表记录必须引用已经存在的主表记录。

## 4. 数据一致性与使用约定

1. **账户初始化**：客户建档时同步创建客户账户，初始余额为 0 分，保证客户与账户的一对一关系完整。
2. **充值一致性**：充值记录生效与客户账户余额增加必须由同一业务事务完成，任一操作失败时整体回滚，避免只记流水或只加余额。
3. **消费一致性**：使用余额结算时，消费记录生效与余额扣减必须由同一业务事务完成，并在扣减前校验可用余额。
4. **金额处理**：所有金额均使用整数分进行存储和计算，不使用浮点数；充值金额必须大于 0，余额和消费金额不得小于 0。
5. **流水保护**：充值和消费记录属于业务流水，不建议随意修改或物理删除；错误记录应通过受控的冲正流程处理。
6. **删除限制**：已有账户、充值记录或消费记录的客户不宜直接物理删除；已有消费记录的手工品类不宜直接物理删除，以保留完整的历史数据和引用关系。
7. **时间口径**：创建时间、修改时间及充值时间均以 UTC 文本保存，展示时再转换为目标时区，避免时区不一致造成偏差。
8. **类型约束**：已确定采用 SQLite 严格表；运行环境需使用 SQLite 3.37 及以上版本，同时保留业务层数据校验。
9. **品类状态**：品类状态以数字枚举存储（1=上架、2=下架），展示文案由前端映射表或多语言资源负责，数据库不保存文案；下架（`status = 2`）后的品类不可再被选择用于新增消费记录，历史消费记录不受影响；品类信息或状态变更时须刷新 `update_time`。
10. **开台一致性**：开台、续时与普通消费共用同一套事务规则——会话写入、消费流水写入与余额扣减必须同事务提交；同一座位已有进行中会话时禁止重复开台，由部分唯一索引 `uk_table_session_active` 兜底。
11. **倒计时口径**：会话只保存 `planned_end_time`（UTC 文本），前端结合接口返回的 `serverTime` 计算剩余时间，不使用本机时钟直接推算；跨设备刷新后以数据库中的计划结束时间为准。
12. **台账衔接**：开台与续时产生的消费流水通过 `session_id` 关联会话；`consumption_record` 的历史数据保持 `session_id = NULL`，原有消费页面与品类统计不受影响。
